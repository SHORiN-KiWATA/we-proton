# 验证范围与结果

整理日期：2026-11-03。网络补丁的历史测试日期：2026-11-01。

## 证据层级

本页区分源码/API 隔离测试、历史已安装运行器、客户端用户复测以及参数化脚本的新增测试。没有把其中一类证据当作另一类证据，也没有执行游戏本体或反作弊适配测试。

历史运行器基于 WE-Proton `4617d991e787603f5300c484f54b4bd61c776090`，另含本地桌面集成补丁 0061，然后依次加入 0062、0063。0061 不修改网络代码；本提案仅包含 0062、0063，**未重新完整构建和实测不含 0061 的整个运行器**。此处数据对应历史受测网络源码，来源见 [PROVENANCE](PROVENANCE.md)。本次提交前的基点、补丁和入口检查另见本页末尾，不等同于重新构建和实测完整运行器。

## 合成路由性能

同一个 PE64 探针、独立无外网容器、3000 条测试路由。每个版本只执行一次完整增删循环；枚举均值来自一次预热后的五次调用，不是大规模统计。

| 操作 | 原桌面基底 | 0062 / netfix1 | 0062+0063 / netfix2 |
| --- | ---: | ---: | ---: |
| GetIpForwardTable2 预热后均值 | 3.6932 ms | 28.2934 ms | 3.4666 ms |
| 创建 3000 条路由 | 3.486292 s | 28.729008 s | 3.650596 s |
| 删除 3000 条路由 | 9.124029 s | 73.151918 s | 9.722433 s |
| 探针失败数 | 0 | 0 | 0 |
| 删除后剩余测试路由 | 0 | 0 | 0 |

0062 的逐项实时接口检查放大了旧路由 API 的全表枚举成本。0063 在一次内部 IPv4 或 IPv6 路由枚举调用内复用成功转换，将性能恢复到接近原基底水平，同时保留后续调用及写入路径的检查。统计数量、读取数据和重试各自进入枚举时重新校验；失败不缓存，缓存分配失败也不丢弃当前已成功转换的有效路由。既有逐路由全表扫描、批量操作近似 O(N²) 的成本仍存在；这不是网络带宽、ping 或 UU 整段连接时间的对比。

可公开的原始合成输出：[基底](../tests/route_perf_probe.wine31-desktop-baseline.txt)、[0062](../tests/route_perf_probe.wine31-desktop-netfix1.txt)、[0063](../tests/route_perf_probe.wine31-desktop-netfix2-candidate.txt)。[探针源码](../tests/route_perf_probe.c)。

## Steam 与客户端

原部署入口通过 26 项隔离检查，另有真实 Steam 的冷启动与已运行客户端 URI 转交测试。通过实际 Steam 启动服务运行普通子进程及 SteamLinuxRuntime 4、sniper、soldier 探针，确认它们与 UU 处于同一 network namespace，并保留测试传入的兼容路径；入口不额外注入 UU 专用 Wine 设置。没有以这些探针结果代替真实游戏兼容性测试。

2026-11-01 最新一轮用户反馈为两款加速目标都能正常加速和停止，同一客户端会话记录到三次完整虚拟接口生命周期。但更早的同版本测试中，第一款成功后第二款仍卡住；后来的成功轮次没有新增生产补丁。因此结论是“一轮真实多目标复测通过”，不是“所有切换卡顿已确定根治”。

成功轮次仍捕获到未开启 SO_BROADCAST 的 raw ICMP socket 向广播地址发送而被拒绝的样本。未部署放开广播的补丁，也未证明这些样本造成之前的挂起。不能将曾在隔离实验中复现的 connected UDP 路由缓存现象误写成实际客户端的已确认根因。

## 启动耗时尚未完全定位

一次完整人工记录的起止间隔为 14.6925 秒，包含切换窗口与反应时间。用户估计记录开始后 3–5 秒才点击加速；据此估算点击到 WintunOpenAdapter 约 4.7–6.7 秒。约 250 ms 间隔的路由采样将路由增长阶段界定为约 2.02–2.53 秒。

这说明创建虚拟网卡前的准备阶段也占有明显等待，尚不能确定是本地初始化还是服务器响应。不能把人工总间隔当作精确点击耗时，也不能把路由阶段耗时当成整个加速启动时间。本提案没有新增针对这段等待的修复。

## 参数化启动脚本

[可选入口](../integration/uu-network/README.md)是对原部署的便携化整理：显式配置运行器、移除本机字体启动器依赖，增加 netns 配置与入口递归保护。该参数化版本的 **45 项隔离测试通过**，覆盖参数转义、环境保留、配置优先级、网络未启用时的拒绝、入口递归检查和 Steam 单实例守卫。

原部署的 26 项检查中有 25 项直接迁移；原来复制实际 wrapper 并改变 HOME 的一项改为更窄的参数契约检查，另外新增 19 项。新测试使用临时 fixture 和 mock，不运行真实 Steam、UU、Wine、pasta 或网络会话，也不改变 HOME。这与上文历史 Steam/Runtime 实机证据是两组不同的验证。文档和提案准备阶段没有重启实际 UU、Steam 或游戏来验证新版本的端到端行为；本次已在提案目录重跑入口测试，结果见下一节。
